# 코호트 선발 진행 지침

## 처리 경계
- 대화 안에 제공된 후보 정보로 하는 간단한 분류·비교·문구 작성은 claw가 즉시 처리한다.
- 레포 파일, 신청서, 인터뷰 기록, 스프레드시트, 프로젝트 문서, 스키마/코드 구현, git 작업이 필요하면 advisor에게 위임한다.
- 선발 기준 자체를 새로 설계하거나 데이터 구조를 정해야 하면 구현·분류 전에 advisor 판단을 먼저 받는다.

## 슬롯 트래킹
- 선발 인원이 변경되는 모든 응답의 첫 줄에 `[확정 N명 / 목표 M명 / 잔여 X자리]` 형식으로 현황을 출력한다.
- 목표 인원이 명시되지 않은 경우 사용자에게 먼저 확인한다.

## 비교표 선제 제공
- 분류 결과(A/B/C 등) 제시 후 잔여 슬롯 수가 확정되면, 사용자가 물어보기 전에 잔여 슬롯 수에 맞춘 우선순위 비교표를 즉시 제공한다.
- 비교표 형식: 이름 / 포지션(그룹 내 역할) / can_give 핵심 / 추천 순위
- 동일 포지션 후보가 2명 이상이면 차별점을 명시한다.

## 후보 병렬 분석 — codex 멀티 에이전트 활용
- 후보가 5명 이상이거나 인터뷰 기록·신청서 등 분석 대상 자료가 분산되어 있으면 codex의 `multi_agent = true`로 후보별 분석을 병렬 처리한 뒤 단일 비교표로 합친다.
- 신청서·인터뷰 로그가 Excel·PDF로 들어오면 codex의 `documents` / `spreadsheets` plugin으로 직접 읽는다.
- 레포 내부 자료 접근이 필요하면 claw가 직접 읽지 않고 advisor에게 위임한다.
- PDF, HTML, 스프레드시트, 문서 파일, URL 등 산출물을 만들었으면 최종 응답 끝에 claw artifact JSON을 붙인다.
  - 파일: `__CLAW_ARTIFACT__ {"kind":"file","path":"C:\\절대\\경로","caption":"설명"}`
  - URL: `__CLAW_ARTIFACT__ {"kind":"url","url":"https://...","caption":"설명"}`

## 최종 확정 후 후속 체크리스트
- "최종 확정", "확정하겠다", "이걸로 가자" 등 최종 결정 발화 감지 시, 응답 말미에 미처리 후속 작업 체크리스트를 자동 출력한다.
- 체크리스트 예시:
  - [ ] 미선발 결제완료자 환불 처리 (N명)
  - [ ] 확정자 안내 (SMS / Discord 초대 등)
  - [ ] 미결제·폼만 제출자 참여불가 안내
  - [ ] 차기 기수 후보 명단 보관

## 실행·검증 규율
- 대화 내 정보만으로 비교표를 만든 경우 최종 보고에 "검증: 슬롯 수/후속 체크리스트 확인"을 포함한다.
- 파일 생성·선발 자동화·반복 워크플로우를 새로 만들거나 수정한 경우 PowerShell 7.6 기준으로 dry-run 또는 실행 검증을 직접 수행한다.
- 레포 변경을 수행했다면 의미 단위로 commit 후 `gh auth setup-git`, HTTPS remote 확인, `git push` 순서로 진행한다. 실패하면 강행하지 말고 보고한다.
- 반복 가능한 선발/분류 워크플로우가 새로 생기면 관련 skill 업데이트를 먼저 제안한다.
