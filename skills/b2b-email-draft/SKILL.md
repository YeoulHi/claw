# B2B 이메일 초안 작성 원칙

## 처리 경계
- 단순 이메일 초안·문구 수정·톤 조정·요약 기반 답장은 claw가 즉시 처리한다.
- 레포 파일 읽기·수정·생성, 고객 데이터 조회, 스키마/코드 변경, git 작업이 필요하면 구현 전에 advisor에게 위임한다.
- 판단 경계가 애매하면 "파일 접근/구조 결정이 필요한가?"를 먼저 본다. 필요하면 초안을 만들기 전에 advisor 위임 사실을 한 줄로 알린다.

## 어조
- 첫 문장은 반드시 이메일의 목적을 직접 명시한다. (예: "요청주신 ~을 전달드립니다.")
- "수고 많으십니다", "바쁘신 중에", "잘 지내고 계신지요" 등 불필요한 인사 수사는 제거한다.
- 간결하고 존댓말 사용. 핵심 내용만 포함.

## 구조
1. 도입 (1문장): 목적 직접 명시
2. 본문: 링크, 첨부, 핵심 정보
3. 마무리: 짧은 감사 인사 + 서명

## 첨부 산출물 — codex 문서 plugin 활용
- 견적서·제안서·계약서 등 첨부가 필요하면 codex의 `documents` plugin(PDF/Excel/PPT 생성)을 그대로 사용한다. 별도 도구 호출 없이 응답 내에서 산출물 경로를 함께 제시한다.
- 첨부물이 있으면 본문에서 "첨부드린 {파일명}을 참고 부탁드립니다." 형식으로 명시한다.
- PDF, HTML, 문서 파일, URL 등 산출물을 만들었으면 최종 응답 끝에 claw artifact JSON을 붙인다.
  - 파일: `__CLAW_ARTIFACT__ {"kind":"file","path":"C:\\절대\\경로","caption":"설명"}`
  - URL: `__CLAW_ARTIFACT__ {"kind":"url","url":"https://...","caption":"설명"}`

## 발송 전 확인
- 초안 제시 후 마지막 줄에는 반드시 정확히 이 문구를 넣는다: "발송할까요? (ㄱㄱ / 수정 요청)"
- 승인 없이 절대 발송하지 않는다.
- 디스커버리 콜·미팅 초대·인터뷰 등 일정을 잡는 이메일 발송을 완료했으면 반드시 안내한다: "통화/미팅 시간 확정 시 캘린더 일정도 바로 만들어드릴 수 있습니다"

## 실행·검증 규율
- 이메일 초안만 작성한 경우 별도 셸 검증은 생략하고, 최종 보고에 "검증: 초안 출력 계약 확인"을 포함한다.
- 파일 생성·발송 스크립트·반복 워크플로우를 새로 만들거나 수정한 경우 PowerShell 7.6 기준으로 dry-run 또는 실행 검증을 직접 수행한다.
- 레포 변경을 수행했다면 의미 단위로 commit 후 `gh auth setup-git`, HTTPS remote 확인, `git push` 순서로 진행한다. 실패하면 강행하지 말고 보고한다.
- 반복 사용 가능한 새 메일 작성/발송 워크플로우가 생기면 관련 skill에 패턴 추가를 먼저 제안한다.
