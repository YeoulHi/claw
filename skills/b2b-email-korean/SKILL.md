# 한국 B2B 이메일 초안 작성 지침

## 처리 경계
- 단순 한국어 B2B 이메일 초안, 제목 제안, 톤 조정, 짧은 답장 문구는 claw가 즉시 처리한다.
- 레포 파일 접근, 고객/프로젝트 기록 조회, 문서 생성·수정, 스키마/코드 구현, git commit/push가 필요하면 advisor에게 위임한다.
- "어떤 구조가 좋을지", "데이터를 보고 판단", "프로젝트 문서 기준"이 포함되면 초안 작성 전에 advisor 판단을 먼저 받는다.

## 초안 작성 전 파악할 것
1. **수신자 정보**: 이름·직함·회사, 기존 거래처 여부
2. **톤**: 격식 / 캐주얼 / 중간 — context에서 추론 가능하면 먼저 제안하고, 불명확하면 한 번에 확인
3. **첨부 파일**: 있으면 제목줄에 [회사명] 태그 포함

## 말투 기준
- 캐주얼 요청 시: "~합니다" 어미 유지, "~고요," 허용
- "같아요" → "같습니다" (비즈니스 맥락 기본값)
- 문장 짧게, 단락 2~3줄 이하

## 서명 포맷 (기본)
감사합니다 :)
{이름} 드림
{소속/브랜드}

## 초안 전달 후 필수 안내
- 초안 출력 말미에는 필요 시 "수정사항 있으면 한 번에 정리해서 주시면 바로 반영하겠습니다"를 덧붙인다.
- 이메일 초안의 마지막 줄에는 반드시 정확히 이 문구를 넣는다: "발송할까요? (ㄱㄱ / 수정 요청)"
- 승인 없이 실제 발송하지 않는다.
- 디스커버리 콜·미팅 초대·인터뷰 등 일정 조율 이메일 발송 완료 후에는 반드시 안내한다: "통화/미팅 시간 확정 시 캘린더 일정도 바로 만들어드릴 수 있습니다"

## 문서/PDF 완성 직후 이메일 요청이 올 경우
- 발송 대상이 맥락에서 파악 가능하면 먼저 제안: "발송용 이메일 초안도 바로 드릴까요? (수신자: {추론된 이름})"
- 수신자 불명확하면 한 번에 확인 후 초안 작성

## 첨부 산출물 — codex 문서 plugin 활용
- 첨부(PDF·견적·제안서·Excel·PPT)가 필요하면 codex의 `documents` / `spreadsheets` / `presentations` plugin으로 직접 생성한다. 외부 도구 호출 없이 응답 흐름 안에서 산출물 경로를 제시한다.
- 첨부 파일 제목줄에는 `[회사명]` 태그 유지, 본문에서는 "첨부드린 {파일명}을 확인 부탁드립니다." 형식으로 안내한다.
- PDF, HTML, 문서 파일, URL 등 산출물을 만들었으면 최종 응답 끝에 claw artifact JSON을 붙인다.
  - 파일: `__CLAW_ARTIFACT__ {"kind":"file","path":"C:\\절대\\경로","caption":"설명"}`
  - URL: `__CLAW_ARTIFACT__ {"kind":"url","url":"https://...","caption":"설명"}`

## 실행·검증 규율
- 초안만 작성한 경우 최종 보고에 "검증: 초안 마지막 줄/발송 승인 문구 확인"을 포함한다.
- 파일 생성·발송 자동화·반복 워크플로우를 새로 만들거나 수정한 경우 PowerShell 7.6 기준으로 dry-run 또는 실행 검증을 직접 수행한다.
- 레포 변경을 수행했다면 의미 단위로 commit 후 `gh auth setup-git`, HTTPS remote 확인, `git push` 순서로 진행한다. 실패하면 강행하지 말고 보고한다.
- 반복 가능한 이메일 업무 패턴이 새로 확인되면 관련 skill 업데이트를 먼저 제안한다.
