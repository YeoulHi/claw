## 문제

일기·리서치·대화가 누적될수록 처음 의도와 다르게 기록된 내용이 증폭된다.
단순히 파일을 "업데이트"하는 것만으로는 부족하다 — 기준 없이 업데이트하면 드리프트가 더 심해질 수 있다.

## 핵심 질문

1. "맥락이 제대로 전달됐다"는 것을 어떻게 검증할 수 있는가?
2. 드리프트(의도와 달라진 내용)를 감지하는 기준은 무엇인가?
3. 재작성이 필요한 시점과 범위를 어떻게 결정하는가?

## 설계 방향

### 검증 기준 (초안)

맥락 문서를 검증할 때 아래 기준으로 평가한다:

| 기준 | 질문 | 판정 |
|------|------|------|
| **의도 일치** | 사용자가 원래 말하려던 것과 문서 내용이 같은가? | 일치 / 드리프트 |
| **출처 추적 가능성** | 이 문서의 내용이 어떤 대화에서 왔는지 역추적할 수 있는가? | 추적 가능 / 불명확 |
| **시효** | 이 내용이 현재도 유효한가, 아니면 상황이 바뀌었는가? | 유효 / 만료 |
| **증폭 위험** | 잘못된 내용이 다른 문서에서 참조되고 있는가? | 없음 / 위험 |

### 드리프트 감지 방법

- advisor가 해당 문서를 **원본 대화 발췌**와 대조
- "이 문서에서 사용자가 실제로 말하지 않은 내용은?" 기준으로 플래그
- 드리프트 심각도: `low` (표현 차이) / `medium` (의미 왜곡) / `high` (의도 반전)

### 재작성 루프

```
검증 → 드리프트 목록 → 사용자 확인 → 재작성 → 재검증
```

- `high` 드리프트: 사용자 확인 후 재작성
- `medium` 이하: advisor가 제안, 사용자가 승인/기각
